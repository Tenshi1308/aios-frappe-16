**Bentuk:** satu *site* Frappe khusus developer (bukan app Next.js terpisah) yang

Kontrak: `docs/03` §1.4 dan `docs/04` Alur 6.

**Fase 1 — Dashboard operasional:**
1. DocType `AIOS Client Site` di site developer: `site_name` (unique), `base_url`,
   `company_name`, `contact_name`, `contact_email`, `api_credential` (`Password`),
   `status` (`Provisioning`/`Active`/`Suspended`/`Decommissioned`), `last_seen`,
   `last_error`, `notes`. **Tanpa `plan`/billing/tiering.**
2. Role `AIOS Control` di site klien (service role, tanpa login manusia): **`read` pada
   `User` dan `AIOS Token Usage` saja**. **Tidak ada akses `AIOS Setting`, tidak ada akses
   DocType bisnis/ERPNext.** Dua tulis lifecycle (`aios_status`, `aios_token_limit`) lewat
   endpoint khusus yang hanya menyentuh dua field itu — bukan `DocPerm write` pada `User`.
3. Control API di site klien (`/api/control/health`, `/users`, `/users/{user}/activate`,
   `/metrics`) dengan validasi token `api_credential`, tolak sesi manusia, audit tiap
   panggilan, mask token di semua error/log. `/metrics` mengembalikan angka agregat saja.
4. Klien HTTP control plane: allowlist `base_url` + wajib HTTPS di non-lokal, guard SSRF
   (RFC1918/loopback/link-local/cloud metadata, re-check redirect).
5. Dashboard: daftar site + status kesehatan, antrean `Pending Provisioning` lintas site,
   aksi aktivasi/suspend, set `aios_token_limit`, monitoring agregat token.
6. Undangan sekali pakai: token set-password dibuat & divalidasi **di site klien**,
   expiry + sekali pakai; control plane hanya menampilkan tautan untuk dikirim manual.
   **Tanpa SMTP untuk PoC**; email otomatis menyusul lewat Email Queue Frappe.
7. `AIOS Admin` target `desk_access = 0`; role itu **tidak dipasang di site klien**;
   `Administrator` tidak pernah dipakai jalur control plane.
